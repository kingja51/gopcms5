PCMS 2026-001 사용자 사이트 와이어프레임 C안 (frame003)

동일한 KRDS 공용 레이아웃 체계·라우트를 유지하되 글로벌 내비를 좌측 고정 다크 사이드바로 옮긴 대안 설계. 상단 가로 GNB 가 없고, 콘텐츠 영역 상단에는 얇은 유틸바(breadcrumb + 검색)만 남는다.

{sc} = siteCode(학과코드 = 서브도메인, 예: ai·med·me). 라우트·보안·데이터 구조는 A안과 동일 — 달라지는 것은 프레젠테이션 계층뿐.

① C안 핵심 차이 (vs A안·B안)
항목A안 (frame001)B안 (frame002)C안 (frame003)
글로벌 내비상단 GNB 밴드 + 호버 드롭다운콤팩트 헤더 + ☰ 메가메뉴 오버레이좌측 고정 다크 사이드바(~220px) — 5그룹 아코디언, 상단 가로 GNB 없음. 모바일은 오프캔버스 드로어
서브페이지 구조본문 1단(와이드) + breadcrumb 밴드페이지 타이틀 밴드 + 좌측 LNB 2단사이드바가 LNB 겸임 — 본문 상단 얇은 유틸바(breadcrumb+🔍)만, 콘텐츠는 인페이지 앵커 탭(스크롤스파이)
홈 히어로풀폭 배너 캐러셀스플릿 히어로(좌 카피·우 이미지)와이드 히어로(이미지+오버레이 카피) → 공지/일정 2컬럼 → 교수진·연구실 가로 스크롤 카드 레일
게시판테이블형 목록 → 상세 페이지카드형 리스트 → 상세 페이지2-pane 분할 뷰(좌 목록 40% + 우 미리보기/상세 60%, 클릭 시 hx-get 부분갱신). 모바일은 목록→상세 페이지 전환
통합검색독립 결과 페이지전체화면 검색 오버레이 + 필터 2단사이드바 상단 인풋 상시 노출 + 결과는 콘텐츠 영역 무한스크롤(htmx revealed)
마이페이지좌측 메뉴 + 대시보드상단 탭 + 카드 대시보드콘텐츠 영역 카드 대시보드(사이드바 프레임 유지, 별도 메뉴·탭 없음)
세 안 모두 KRDS 규약(시맨틱 토큰·htmx+순수JS·네이티브 <dialog>/<details>·CSP nonce·이벤트 위임) 안에서 구현 가능. 사이드바 아코디언·사이트맵·모바일 드로어는 전부 siteContext.menuTree 재사용 — 추가 데이터 불필요.

파일화면대표 라우트

home.html홈 — 와이드 히어로·공지/일정 2컬럼·포토앨범/연구실 카드 레일/{sc}/home
content.html콘텐츠 — 인페이지 앵커 탭(스크롤스파이) 학과소개·오시는길/{sc}/about · /{sc}/location
program.html프로그램 — 좌측 필터 패널 + 카드 그리드 교수진 (직원·연구실·수업계획서 변형)/prg/{program}/{sc}

search-sitemap.html검색(무한스크롤 결과) · 사이트맵(사이드바 트리 풀 확장 뷰 — 4뎁스 전체)/search · /{sc}/sitemap
common.html공통 프로그램·보조 화면 (학사일정·알림함·계정찾기·설문·민원·파일뷰어·오류)/schedule · /notification · /member/find-* · /survey · /complaint
표기 규칙: 회백 실선 = 정적 마크업, 청록 점선 = htmx/JS 동적 슬롯, 청록 주석 = 구현 메모. (A안 파랑·B안 주황과 구분) 브라우저바 URL 은 개발 서버 형식(http://127.0.0.1:8080/{sc}/…) — 운영은 서브도메인이 {sc} 로 해석됨.
③ 정보구조(IA) — A안과 동일 (메뉴 5그룹 · 최대 4뎁스)
/{sc}/home · 소개(학과소개 /{sc}/about · 오시는길 /{sc}/location) · 구성원(교수진 /prg/faculty/{sc} · 직원 /prg/staff/{sc})
· 교육(교과과정 /{sc}/curriculum · 수업계획서 /prg/syllabus/{sc} · 학사일정 /schedule/{master}) · 연구(연구실 /prg/lab/{sc} · 연구성과 /bbs/{sc}/pub)
· 커뮤니티(공지 /bbs/{sc}/notice · 학과소식 /bbs/{sc}/news · 세미나 · 자료실 /bbs/{sc}/archive) · 회원(/member/**) · /search
· 3뎁스 예: 교과과정 › 학부·대학원, 공지 카테고리(학사·장학·취업) — 4뎁스 예: 학부 › 전공필수·전공선택, 학사서식 › 휴·복학/졸업 서식
메뉴 뎁스 출력 규칙(전 안 공통) — 사이드바 메뉴(아코디언)는 1~3뎁스까지만 노출, 4뎁스는 메뉴에 노출하지 않고 3뎁스 페이지 내 탭/필터로 처리. 사이트맵(/{sc}/sitemap)만 1~4뎁스 전체 전개. 데이터는 siteContext.menuTree 하나(depth 1~4 저장) — 사이드바·사이트맵이 렌더 뎁스만 달리한다. IA·라우트·tb_menu 시드는 A안과 동일 — 달라지는 것은 프레젠테이션 계층뿐. C안은 같은 메뉴 트리를 사이드바 아코디언으로 렌더한다. 상세 트리는 frame001/index.html ② 참조. 새 URL 은 tb_role_url_access 등록 필수(무매칭 DENY) — 규칙도 세 안 공통.

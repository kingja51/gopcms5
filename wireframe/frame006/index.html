PCMS 2026-001 사용자 사이트 와이어프레임 F안 (frame006)

콘셉트: 모바일 퍼스트 앱형 — 모든 화면을 모바일 프레임(~390px, 하단 고정 탭바 5개)으로 먼저 그리고, 데스크톱은 같은 5탭을 상단 가로 내비로 전개한 센터 협폭(~860px) 1컬럼으로 확장. "모바일이 정본, 데스크톱은 확장" 관점 — 별도 모바일 사이트가 아니라 하나의 Thymeleaf 템플릿이 반응형으로 두 모습을 낸다.

{sc} = siteCode(학과코드 = 서브도메인, 예: ai·med·me). 라우트·보안·데이터 구조는 A안과 동일 — 달라지는 것은 프레젠테이션 계층뿐.

① F안 핵심 차이 (vs A~E안)
항목 A안
표준 GNB형		 B안
콤팩트 헤더+LNB		 C안
좌측 사이드바+2-pane		 D안
풀블리드 원페이지 에디토리얼		 E안

모바일 퍼스트 앱형
글로벌 내비 상단 GNB 밴드 + 호버 드롭다운 콤팩트 헤더 + ☰ 메가메뉴 오버레이 좌측 사이드바 상주 내비 미니멀 헤더 + 풀스크린 메뉴 포털 상단바 + 카드 진입 하단 고정 탭바 5개(홈·학과·게시판·검색·MY) — 데스크톱은 같은 5탭이 상단 가로 내비
서브페이지 구조 본문 1단 와이드 + breadcrumb 페이지 타이틀 밴드 + 좌측 LNB 2단 2-pane(좌 목록 · 우 상세) 섹션 스크롤 원페이지 대시보드 → 카드 상세 콤팩트 앱바(뒤로가기/타이틀) + 협폭 1컬럼, 긴 콘텐츠는 아코디언 분절
홈 풀폭 캐러셀 + 바로가기 타일 스플릿 히어로 + 탭 위젯 + 통계 밴드 사이드바 + 콘텐츠 피드 에디토리얼 히어로 + 매거진 섹션 벤토 카드 그리드 가로 스와이프 히어로 카드 + 아이콘 퀵메뉴 2행 + 공지 피드 + 일정 스트립
게시판 테이블형 목록 카드형 리스트 + LNB 2-pane 마스터·디테일 매거진형 리스트 위젯 카드 목록 피드형 카드 무한스크롤(hx-trigger="revealed") + 글쓰기 FAB, 상세는 하단 고정 액션바
검색 독립 결과 페이지 전체화면 검색 오버레이 사이드바 필터 결과 커맨드 팔레트형 대시보드 검색 위젯 탭바의 "검색" 탭 자체가 검색 홈 — 최근/인기 칩 → 자동완성 → 결과 무한스크롤
마이페이지 좌측 메뉴 + 대시보드 상단 탭 + 카드 대시보드 2-pane 설정 프로필 원페이지 위젯 보드 MY 탭 — 프로필 헤더 + iOS 설정 스타일 리스트 그룹
여섯 안 모두 KRDS 규약(시맨틱 토큰·htmx+순수JS·네이티브 요소 우선·CSP nonce·self-host) 안에서 구현 가능. F안의 하단 탭바는 CSS(position:fixed)만으로 구성 — JS 프레임워크 금지 규약 그대로. 탭 active 판정은 서버 렌더(현재 URL 매칭)라 JS 불필요. 메뉴 뎁스 출력 규칙(전 안 공통) — 메뉴("학과" 탭 전체메뉴·데스크톱 드롭 패널)는 1~3뎁스까지만 노출, 4뎁스는 3뎁스 페이지 내 탭/필터로 처리. 사이트맵만 1~4뎁스 전체 전개. 데이터는 siteContext.menuTree 하나(depth 1~4 저장) — 렌더 뎁스만 달리함.
② 와이어프레임 목차
파일화면대표 라우트
layout.html공용 프레임 해부도 — 모바일(앱바+탭바 5개) / 데스크톱(상단 5탭+협폭 컬럼) · "학과" 탭 전체메뉴·드롭 패널(1~3뎁스)전 페이지 공통 프레임
home.html홈 — 인사/검색 스트립·스와이프 히어로 카드·퀵메뉴 2행·공지 피드·포토앨범 스트립·일정 스트립/{sc}/home
content.html콘텐츠 — 아코디언 분절 학과소개·풀폭 지도 오시는길/{sc}/about · /{sc}/location
program.html프로그램 — 연락처 앱형 교수진 리스트·ㄱㄴㄷ 인덱스·바텀 시트 프로필/prg/{program}/{sc}
board.html게시판 — 피드형 무한스크롤 + FAB · 상세 하단 액션바/bbs/{sc}/{bbsCode}
member.html회원 — 풀페이지 로그인(소셜)·한 화면 한 질문 가입·MY 탭 설정 리스트/member/**
search-sitemap.html검색 탭(최근·인기·자동완성·결과) · 사이트맵 풀 뷰(1~4뎁스 전체 전개)/search · /{sc}/sitemap?view=full
common.html공통 프로그램·보조 화면 (학사일정·알림함·계정찾기·설문·민원·파일뷰어·오류)/schedule · /notification · /member/find-* · /survey · /complaint
표기 규칙: 회색 실선 = 정적 마크업, 하늘색 점선 = htmx/JS 동적 슬롯, 스카이블루 주석 = 구현 메모. 각 페이지는 모바일 프레임(정본)과 데스크톱 캔버스(확장)를 나란히 병기. 브라우저에서 직접 열면 됨(서버 불필요).
③ 하단 탭바 5개 ↔ 라우트 매핑
탭라우트비고
🏠 홈/{sc}/home스와이프 히어로 + 퀵메뉴 + 공지 피드
🎓 학과/{sc}/sitemap전체메뉴(메뉴 5그룹 아코디언, 1~3뎁스 노출) — tb_menu 트리를 앱의 "둘러보기" 탭으로 렌더. 사이트맵 풀 뷰(?view=full)만 1~4뎁스 전체
📋 게시판/bbs/{sc}/notice커뮤니티 그룹 첫 게시판으로 진입, 상단 칩으로 게시판 전환
🔍 검색/search?siteCode={sc}검색 홈(최근/인기) → 자동완성 → 결과
👤 MY/member/mypage비로그인 시 /member/login 으로 — 무매칭 DENY 아닌 인증 리다이렉트
IA·라우트·tb_menu 시드는 A안과 동일 — 달라지는 것은 프레젠테이션 계층뿐. 메뉴 5그룹(소개·구성원·교육·연구·커뮤니티) 상세 트리는 frame001/index.html ② 참조. 출력 규칙(전 안 공통): 메뉴 = 1~3뎁스, 사이트맵 = 1~4뎁스 — 4뎁스(전공필수·전공선택, 석사·박사과정, 휴·복학/졸업 서식)는 메뉴 미노출, 3뎁스 페이지 내 탭/필터로 처리. siteContext.menuTree 하나로 렌더 뎁스만 달리함. 탭바가 새 URL 을 만들지 않으므로 tb_role_url_access 추가 등록도 불필요(기존 규칙 그대로 — ?view=full 은 쿼리 파라미터).
